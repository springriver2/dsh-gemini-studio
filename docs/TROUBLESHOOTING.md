# 踩坑记录

这里记的都是**实际踩过、并且已经改掉**的问题。按「症状 → 原因 → 处置」写，方便下次改版后再遇到时对照。

---

## 一、Gemini 侧（最容易变）

### 1. 聊天里点「制作视频」，返回「我只是一个语言模型」

- **症状**：走 `gemini.google.com/app` 的「上传和工具 → 制作视频」，选中视频工具、填好提示词发送，得到一段文本拒绝；会话底部模型标签仍写着「视频 Flash」。
- **原因**：2026-11 起视频生成搬到了独立的 `gemini.google.com/videos` 页面。聊天里那个入口还在，但已经不出片。
- **处置**：桥改为直接导航到 `/videos` 发起生成。旧入口一律不要再用。

### 2. 首帧图挂载失败（`+` 点了没反应）

- **症状**：`首帧图挂载失败`，日志里 `挂图重试 1/2/3`。页面上点 `+`（aria-label「上传和工具」）既不弹菜单也不弹文件框；拖放也不接收。
- **原因**：Gemini 的挂图交互改版；`input[type=file]` 在 DOM 里不存在，`+` 的行为依赖版本。
- **处置（已实现，按顺序尝试）**：
  1. 点 `+` → 若出现「上传文件」菜单项就点它 → 用 AppleScript 驱动系统文件框填路径（需要宿主有「辅助功能」权限）
  2. 退回 CDP 拖放（`Input.dispatchDragEvent`），拖放目标优先 `[xapifileselectordropzone]`
- **仍未通时**：手动把那一次的首帧拖进 Chrome 窗口，其余步骤照常。

### 3. 掉登录 / 被要求验证

- **症状**：页面跳到 `accounts.google.com`，或出现「确认是你本人」「异常流量」。
- **处置**：桥会抛 `ChallengeError` 并**立刻停机**，把该账号锁 7 天。**不要重试**，人工处理后再 `gemini_accounts reset`。

### 4. 额度类失败

- **症状**：`HTTP 429`、`找不到视频入口`、`所有 Gemini 账号都在冷却或被占用`。
- **处置**：立刻停止提交，不要重试——每次重试都是一次真实额度。等冷却（5 小时一档）或加号。

### 5. 多账号音色不一致

- **症状**：原生语音（Gemini 自己念台词）时，不同镜头的嗓音不一样。
- **原因**：每镜是独立推理，声音身份不保证跨镜一致。
- **处置**：接受（用一条条镜头对齐台词）；或改用 TTS 统一音色 + 画面不露嘴（见下）。

## 二、Chrome / CDP

### 6. `CDP 超时：Page.enable`

- **症状**：体检报「登录异常 / 输入框缺失」，页面看着正常。
- **原因**：Chrome 自动升级后那个 profile 的标签页卡死。
- **处置**：`pkill -f "user-data-dir=~/.gemini-video-bridge/profiles/<id>"`，让桥重新拉起。登录态不受影响。

### 7. 桥的任务一直 `running`，页面其实已经出片

- **症状**：任务不结束，但浏览器里视频已经生成好了。
- **原因**：**同一时间只允许一个 CDP 客户端连同一个标签页**。你在桥跑任务时开了调试脚本，把桥的调试连接挤掉了。
- **处置**：排障要么等任务结束，要么先停桥。桥现在连续 5 次探测失败会判「调试连接已断开」并重连回原会话。

### 8. Chrome 窗口被关了还能继续用吗

能。登录态在 profile 目录里，关闭窗口不等于退出登录；下次生成会自动重新拉起同一个 profile。

## 三、合成（ffmpeg）

### 9. 有配音 + 有转场就崩

- **症状**：`Invalid file index 3 in filtergraph` / `转场合成失败`。
- **原因**：filter_complex 里音频输入索引算错一位（音频输入从第 `k` 个开始，代码写成 `k+1`）。
- **处置**：`audio_parts(len(paths) - 1)`。

### 10. 第二处转场必崩

- **症状**：`First input link main timebase (1/1000000) do not match ... (1/15360)`。
- **原因**：`xfade` 链式拼接时，中间结果的时间基与下一路输入不一致。
- **处置**：每路输入先 `fps=<fps>,settb=AVTB` 归一到同一时间基。

### 11. 成片是 yuv444p，播放器/平台不认

- **症状**：`xfade` 输出的视频流变成 `yuv444p`。
- **处置**：输出显式加 `-pix_fmt yuv420p`。

### 12. 字幕是豆腐块（□□□）

- **症状**：中文全渲染成方框。
- **原因**：默认样式写的是 `Microsoft YaHei`（Windows 字体），macOS 的 libass 找不到；`PingFang SC`、`STHeiti` 实测也不行。
- **处置**：按平台选字体，macOS 用 **Hiragino Sans GB**（实测唯一正常），Windows 用雅黑，Linux 用思源。

### 13. 字幕撑出画幅，左右被裁

- **原因**：`FontSize=10` 在 libass 默认 PlayResY=288 下，720 宽竖屏放不下 16 个字。
- **处置**：默认 `FontSize=8`。

### 14. 长句不折行 / 英文被劈开

- **处置**：按语言折行——中文按字数（每行 ≤16 字），拉丁按词（按字数会把 `energies` 劈成 `energi / es`）。

### 15. 成片尾部冻住

- **原因**：总时长按「配音估算」撑大，画面不够长，最后一帧被定格。
- **处置**：用每段配音的**真实时长**算总时长；配音超出画面时只警告，不硬撑。

### 16. 人物话没说完就切

- **原因**：每镜固定剪入 7.5 秒，但模型念一句英文可能要 8.6 秒。
- **处置**：`retime_shots` 用静音检测找自然停顿，把剪入终点落到停顿上（只在目标时长前后 2.5 秒内找，避免把镜头拉太长）。

### 17. 原生语音下字幕和声音对不上

- **原因**：字幕按「镜头起点 + 0.25 秒」硬排，没有跟真实人声走。
- **处置**：原生语音时先检测每镜的人声起止，再用它生成字幕时间轴。

## 四、DSH 插件

### 18. 整轮对话直接 `INVALID_REQUEST`，报 `true is not of type "array"`

- **原因**：工具参数里用了 Cordis 方言的 `required: true`（布尔）。发给模型时被序列化成非法 JSON Schema，**每个请求都会失败**，不只是那个工具。
- **处置**：参数和输出 schema 一律用对象级 `required: ["a","b"]` 数组。

### 19. 面板所有按钮点了没反应（POST 404）

- **原因**：`webServer.register({ resource })` 这种 resource 路由**只答 GET/HEAD**，POST 会掉到 SPA 兜底。
- **处置**：改成 Node 的 `handler(req, res)` 形式。

### 20. 面板路由注册不上

- **原因**：`ctx.get("webServer")` 在 `apply` 执行时可能还没 ACTIVE。
- **处置**：用 `ctx.inject(["webServer"], inner => …)` 等它就绪再注册。

### 21. 插件启动桥失败（Electron 宿主）

- **原因**：宿主是 Electron 时 `process.execPath` 指向 App 本体，不是 node。
- **处置**：spawn 时补 `ELECTRON_RUN_AS_NODE=1`。

### 22. `media_verify` 报 `No module named 'PIL'`

- **原因**：系统 python3 没装 Pillow。
- **处置**：优先用 DSH 自带的 python（`~/.dsh/dsh-runtimes/*/dependencies/python/bin/python3`），它带 Pillow。

### 23. 系统 ffmpeg 直接崩（`Symbol not found: _x265_api_get_215`）

- **原因**：Homebrew 的 ffmpeg 与 x265 版本错位，光做软链也没用（符号版本不同）。
- **处置**：用内置静态 ffmpeg（`tools/ffmpeg/node_modules/ffmpeg-static`），插件自动优先使用它。

### 24. 桥重启后项目里留下「在途任务」，新任务提交不了

- **症状**：`有尚未结束的任务，请先回查原任务`。
- **原因**：桥的任务在内存里，重启即丢；项目 `tasks.json` 还记着 `submitted`。
- **处置**：回查桥的 `/task/<id>`；确实丢了就把该 attempt 标为 failed（必要时手工补录已经生成的片子）。

## 五、操作约定（别再踩）

- 每个镜头版本只能有一个同模式任务；**要重生成必须先升版本**（`v001 → v002`），否则 CLI 会拒绝。
- 改台词后：改 `storyboard.json` → 重跑 `tts_generate` → `retime_shots` → 重新验收 → `short_compose`。
- 交付前必跑 `media_verify`（防白屏、核对配音窗口），不要只靠肉眼看。
